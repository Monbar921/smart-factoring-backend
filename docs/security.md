# Данные, безопасность и комплаенс

Как Smart Factoring обращается с данными клиентов банка: что обрабатывается, кто что видит, что уходит наружу и что
нужно для пилота в контуре ВТБ. Документ описывает систему как она есть; что появится только на пилоте, помечено.
Решения с номерами Р-N — [claude/02-decisions.md](claude/02-decisions.md).

## Какие данные обрабатываются

| Данные | Откуда в MVP | Откуда на пилоте | Класс |
|---|---|---|---|
| Покупатели: ИНН, ОГРН, наименование, ОКВЭД, регион, отчётность | открытые данные: ГИР БО (RFSD), ЕГРЮЛ, ЕФРСБ | те же + сервис проверки контрагентов банка | открытые сведения о юрлицах |
| Клиенты (поставщики): ИНН, наименование, отрасль, ликвидность, менеджер | синтетика | хранилище банка, CRM | банковская тайна (ст. 26 Закона «О банках и банковской деятельности») |
| УПД, договоры, платежи клиента по покупателям | синтетика | ЭДО (с согласия клиента), выписки | банковская и коммерческая тайна |
| Оценки: PD, задержка, уровень риска, предложение, решение менеджера | расчёт системы | расчёт системы | внутренняя информация банка |
| Пользователи: логин, роли | Keycloak стенда | IAM банка | персональные данные работников |

В демо персональных данных нет (НФР-10): покупатели — юрлица из открытых источников, клиенты, УПД и платежи
синтетические. На пилоте персональные данные появятся: клиенты-ИП (ФИО, ИНН физлица), подписанты УПД, логины
сотрудников. Для них — обработка в контуре банка по его политике 152-ФЗ; модели и LLM их не получают (см. ниже).

## Согласие клиента

Клиент без согласия на анализ данных ЭДО (`edo_consent = false`) в прогон не попадает: блок 1 отбирает только клиентов
с согласием и без действующего факторинга. В демо это контрольный клиент «Без-Согласия». На пилоте признак согласия
берётся из CRM банка.

## Кто что видит

```
браузер ──Keycloak (OIDC, PKCE)──▶ токен
   └─ /api/** + Bearer ──▶ ui (nginx) ──▶ gateway ──▶ backend ──▶ ml
                                         │ подпись, issuer, срок токена;
                                         │ роли на путях
                                         └─ без токена - 401, до backend не доходит
```

| Роль | Что доступно |
|---|---|
| `operator` | экран процесса: загрузка данных, запуск анализа, результаты, журнал |
| `manager` | эмулятор CRM: очередь, карточки, уведомления, «Передать» / «Отклонить» — **только по своим клиентам** (НФР-9, Р-75) |
| `supervisor` | эмулятор CRM по всем менеджерам (руководитель) |
| гостевой вход «Запуск демо» | всё только для просмотра: изменяющие запросы отклоняет gateway |

- Токен проверяет gateway (ключи realm Keycloak, issuer, срок). Backend и сервис моделей наружу не опубликованы и
  доступны только из сети стенда.
- Чей менеджер пользователь — по логину из токена (`MANAGER_LOGINS`, на пилоте — из CRM). Чужая карточка или
  предложение — `403`, отказ пишется в лог backend.
- Postgres доступен только внутри Docker-сети и на `127.0.0.1` сервера (для IDE через SSH-туннель). У каждого стенда
  своя база и пользователь, чужие базы ему недоступны.

## LLM: что уходит наружу

LLM пишет менеджеру объяснение оценки и черновик сообщения клиенту. Решение (предлагать или нет, сумма, цена) LLM не
принимает: его считает код по правилам BRD.

| Защита | Как работает |
|---|---|
| Маскирование (Р-73) | В LLM вместо названия клиента, названия и ИНН покупателя и номера УПД уходят метки `CLIENT_1`, `BUYER_1`, `INN_1`, `UPD_1`; настоящие значения backend подставляет в ответ. Любые числа длиной ИНН и ОГРН в любом запросе к LLM тоже заменяются метками. Суммы, даты и уровень риска остаются: по ним одним клиента не узнать. Включено по умолчанию (`LLM_MASK=true`) |
| LLM в контуре (Р-74) | `LLM_MODE=onprem`: сервер с API вида OpenAI в сети банка (vLLM, Ollama) и открытая модель (T-lite / T-pro, GigaChat Lite, Qwen). Данные не покидают контур. Рассуждение моделей с «мышлением» (`<think>`) менеджеру не показывается |
| Российская облачная LLM | `LLM_MODE=gigachat`: GigaChat API, TLS с корневым сертификатом НУЦ Минцифры |
| Проверка ответа (Р-59) | Ответ с оценками или обещаниями, которых нет во входных фактах, или с искажённой меткой — повтор, затем шаблонный текст. Менеджер видит источник текста (LLM, кеш, шаблон) |
| Без LLM | `LLM_MODE=stub` или `off`: шаблонные тексты, система работает полностью |

Сервис моделей (PD, задержка) — свой код в контуре, внешних вызовов не делает; к LLM ходит только через backend, с
тем же маскированием.

## Журнал для аудита (НФР-7)

| Что | Где хранится |
|---|---|
| Запуск анализа: кто, роль, когда, набор клиентов, дата расчёта, версии моделей и текстов | `run`, `run_log` |
| Попытки запуска, в том числе отклонённые (нет прав, уже идёт, данные уже проанализированы) | `run_attempt` |
| По каждому УПД: клиент, покупатель, оценка, решение, причина отказа, сумма до и после деления лимита | результаты шагов прогона |
| Решение менеджера: кто, когда, по какому предложению, комментарий к отказу | `offer.decided_by`, `offer.decided_at` |
| Пакеты, переданные в ВТБ Факторинг, и сигналы в риск | `imitation_factoring_package`, `imitation_risk_signal` |
| Отказы в доступе | лог gateway (роли на путях) и лог backend (чужой клиент) |

Срок хранения — по требованиям банка, на пилоте.

## Секреты

- Пароли БД, ключ GigaChat, секреты гостевого входа — в секретах окружений GitHub (`test`, `prod`); на сервер они
  попадают в `.env` с правами только для владельца. В репозиториях секретов нет; локальный `.env` в git не
  отслеживается, шаблон — `.env.example`.
- Ключ деплоя по SSH — отдельный, только на каталог стенда; токен для вызова деплоя — fine-grained, только на
  репозиторий smart-factoring-deploy.
- Сервисы в контейнерах работают не от root.
- **Проверка секретов в CI** (Р-77): в каждом репозитории workflow `secret-scan.yml` на каждый push и pull request —
  gitleaks по файлам репозитория (правила по умолчанию, исключения — `.gitleaks.toml`: тесты, шаблоны `.env.example`,
  публичные корневые сертификаты) и запрет отслеживаемого `.env`. Красная проверка — секрет попал в git: убрать его
  из репозитория и сменить сам секрет, он уже в истории публичного репозитория.
- **Аудит истории (21.11.2026)**: во всех пяти репозиториях искали закрытые ключи, токены GitHub, JWT, файлы ключей и
  `.env`. Найден один случай — `.env` с логином и паролем администратора локальной Postgres разработчика (порт 5433)
  в истории smart-factoring-backend; в git он больше не отслеживается. Пароль совпадает с паролем в другом проекте
  разработчика и подлежит смене везде, где используется. В локальном `test.env` стенда test его нет; секреты стендов
  в GitHub (`POSTGRES_PASSWORD_ADMIN` и др.) владелец проверяет сам. Историю git не переписываем: репозитории публичные и уже склонированы, переписывание не отзывает утёкший
  пароль — отзывает только его смена.

## Регуляторика

| Требование | Как учитываем |
|---|---|
| 152-ФЗ «О персональных данных» | В демо персональных данных нет. На пилоте: обработка только в контуре банка, маскирование перед LLM, LLM в контуре, доступ по ролям и закреплению за менеджером, журнал действий |
| Банковская тайна | Данные клиентов не покидают контур; во внешнюю LLM — только метки вместо названий и реквизитов |
| 115-ФЗ (ПОД/ФТ) | Система не заменяет проверки ВТБ Факторинга: предложение — подсказка менеджеру, сделку и проверки проводит фактор. Стоп-факторы по ЕГРЮЛ и ЕФРСБ уже отсекают покупателей; на пилоте — подключение перечней Росфинмониторинга и данных ФССП, арбитража, налоговой задолженности |
| Информационная безопасность банка | Развёртывание on-prem (Docker Compose, далее Kubernetes банка), без обязательного доступа в интернет при `LLM_MODE=onprem`; авторизация через IAM банка вместо Keycloak стенда |
| Российское ПО | PostgreSQL (совместим с Postgres Pro), GigaChat или открытые модели в контуре, открытые компоненты без облачных зависимостей |

## Модель угроз (кратко)

| Угроза | Мера | Статус |
|---|---|---|
| Утечка данных клиентов через внешнюю LLM | маскирование, LLM в контуре | сделано |
| Менеджер смотрит чужих клиентов | закрепление клиентов за менеджером, 403 | сделано |
| Обращение к API без авторизации | gateway проверяет токен; backend и ml не опубликованы | сделано |
| LLM выдумывает условия или оценки | проверка ответа по фактам, шаблон при повторном домысле | сделано |
| Ошибочное предложение при сбое модели | «неверное предложение хуже, чем никакого» (НФР-4.1): нет оценки — нет предложения | сделано |
| Перехват трафика | стенд хакатона работает по HTTP; на пилоте — TLS на всех внешних точках (UI, gateway, Keycloak) | на пилоте |
| Утечка секретов из репозитория | секреты в GitHub Secrets; проверка gitleaks на каждый push во всех репозиториях; `.env` удалён из git, пароль из его истории сменить вручную | частично: смена пароля за владельцем |
| Подмена данных источников | имитации в MVP; на пилоте — подписи ЭДО и интеграции банка | на пилоте |
