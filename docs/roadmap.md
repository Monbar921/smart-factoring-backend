# Дорожная карта до финала «Финтех без границ»

Составлена 16.11.2026 по условиям соревнования (трек «Банк будущего для бизнеса и клиентов»), BRD 2.1 и состоянию
репозиториев backend, ui, ml, gateway, deploy на ветке `feature/SMF-33`. Презентация и папка с аналитикой при
составлении не просматривались: пробелы по финансовой модели и плану пилота выведены только из репозиториев.

## Этап 1. Спринт 2 (16–29 ноября)

Порядок внутри этапа - по убыванию отдачи в баллах на день работы.

### 1.1. Защита данных и комплаенс (18 баллов)

| № | Работа | Где | Готово, когда |
|---|---|---|---|
| 1 | Маскирование данных перед LLM: названия компаний, ИНН и номера УПД заменяются метками и подставляются обратно в ответ | backend, `factoring/llm` | В запросе к GigaChat нет названий и ИНН; тексты в карточке прежние |
| 2 | Режим on-prem LLM: клиент с OpenAI-совместимым API рядом с `stub`, `gigachat`, `off` | backend, `factoring/llm` | Прогон проходит на локальной модели, режим переключается переменной |
| 3 | Убрать `.env` из git и сменить пароль администратора БД | backend | Файл не отслеживается, пароль на стенде новый |
| 4 | Доступ менеджера по токену, а не по выбору в эмуляторе CRM (НФР-9) | gateway, backend, ui | Менеджер видит только своих клиентов, чужая карточка - 403 |
| 5 | HTTPS на стенде, `sslRequired` в realm | deploy | UI, gateway и Keycloak открываются по HTTPS |
| 6 | Документ `docs/security.md`: классы данных, что относится к персональным данным (ИП, подписанты), 152-ФЗ, 115-ФЗ, банковская тайна, модель угроз, журнал для аудита, схема размещения on-prem | backend, docs | Документ лежит в аналитике загрузки, на него есть слайд |

Ход работ (21.11.2026), решения — Р-73…Р-75 в [claude/02-decisions.md](claude/02-decisions.md):

| № | Статус | Что сделано и что осталось |
|---|---|---|
| 1 | сделано | Метки вместо названий, ИНН и номеров УПД, обратная подстановка; ИНН и ОГРН маскируются в любом запросе к LLM. Проверено тестом против заглушки GigaChat |

| 3 | частично | `.env` не отслеживается, есть `.env.example`. Пароль из истории git нужно сменить вручную везде, где он использовался |
| 4 | сделано | `MANAGER_LOGINS`, роль `supervisor`, 403 на чужое. Перед выкатом — роль `supervisor` в Keycloak, см. README smart-factoring-deploy |
| 5 | не начато | Нужен домен для сертификата; затем TLS-прокси перед UI, gateway и Keycloak, `sslRequired` и redirect URI в realm |
| 6 | сделано | [security.md](security.md); слайд — за презентацией |

## Этап 3. Финал (11 декабря)

- Репетиция питча на стенде и запасное видео на случай сбоя.
- Проверка стенда за день до финала: свежий прогон, ключ GigaChat, срок сертификатов.
- Ответы на ожидаемые вопросы жюри: модель задержки обучена на синтетике; TR - правило, а не модель; что нужно от
  банка для пилота.

## Что не делаем

- Подключение нового покупателя (лимит до порога, ручная проверка).
- Реальные интеграции с ЭДО, выписками и CRM.
- Отдельное приложение для клиента банка.

Каждое из них дорого и даёт меньше баллов, чем работы выше; в презентации они остаются в плане развития
(BRD, Приложение В).
