## Что показала сверка с кодом

- **Тексты к УПД-0280 (П2-3.1, 3.2).**
  - Покупатели из партий ML-команды получают PD из партии через кеш PD (Р-54) с пустым списком причин.
  - В LLM уходит пустой блок «Главные причины оценки покупателя», и модель, по всей видимости, заполняет его пометками
    («вероятна задержка», «уменьшено до лимита»).
  - Пометка в карточке и признак в фактах для LLM берутся из одного места (`decision.reducedToLimit`), источник один.
    «Уменьшено до остатка лимита» в тексте при отсутствии пометки — выдумка LLM, а не расхождение данных.
  - Проверить на стенде по УПД-0280: `buyer_score.reasons` и `pd_source` покупателя 9725077448.
- **Версия промптов (П2-3.4).**
  - На стенде показывается `gigachat:GigaChat-2:v3` (версии моделей прогона). Версии «v2 после слияния SMF-36» в
    нашем коде нет: v2 и v3 — наши номера (Р-58, Р-59).
  - С Р-60 сами тексты промптов входят в ключ кеша: после деплоя работают ровно те `llm/*.txt`, что в репозитории.
- **«УПД № УПД-0280» (П2-4).** Повтор идёт из фактов, которые backend передаёт в LLM («УПД: № УПД-0280»). Правим
  у себя в фактах (`UpdNumber.labelWithNo`) — промпт тогда не нужно учить этому правилу.
- **Ожидаемый доход (П2-2.3).** Ранг очереди уже равен TR × доход банка, сортировка по нему уже есть; `tr` и `rank` уже
  есть в ответе очереди. Нужна только колонка и подсказка.
- **Задержка в карточке (П2-2.11).** В `OfferDto` нет вероятности задержки и порога — нужно добавить в API.
- **Партии (П1-1).** Привязка клиента к партии нигде не хранится: при импорте партии `batch_id` есть только в
  `manual_upload_batch.source_name`.
- **Воронка (В).** У шагов в коде больше причин, чем в документе. Для них нужны названия и цвета (вопрос 3 ниже):
  - шаг 2 — ещё «уже есть решение менеджера»;
  - шаг 5 — ещё «ошибка оценки»;
  - шаг 6 — ещё «вероятна просрочка 90+» и «лимит исчерпан» (до деления лимита).

## Вопросы, которые были

1. **Гостевой вход: как гость получает доступ.** Предлагаем gateway выдаёт токен демо-пользователя, без пароля в
   браузере. Альтернатива — публичный демо-логин и пароль на странице: проще, но пароль виден всем.
2. **Гостевой вход: что гостю можно менять.** Демо-данные у всех общие — отделить «данные, которые загрузил гость»
   от остальных нельзя без отдельной схемы на гостя. Предлагаем:
   - гость смотрит и запускает прогоны;
   - загружать данные и принимать решения в CRM гостю нельзя.

   Разрешить загрузку партий — значит, гость может изменить данные для всех (только добавить: импорт — дельта,
   ничего не стирает).
3. **Воронка: причины, которых нет в документе.** Названия и цвета:
   - «уже есть решение менеджера» (шаг 2);
   - «ошибка оценки» (шаг 5);
   - «вероятна просрочка 90+» и «лимит исчерпан» до деления (шаг 6).

   Предлагаем названия в том же стиле и нейтральные цвета из палитры.
4. **Теги требований (ЭП-1…ЭП-9) в углах блоков.** Документ убирает «ЭП-4» у воронки. Убрать у всех блоков экрана
   или только у воронки?
5. **Ярлык «составлено автоматически» (П2-2.10, «по желанию»).** Делаем, а различие LLM, кеш, шаблон оставляем в
   подсказке?
